# infra-import

**Turn your existing AWS account into clean, organized Terraform in one command.**

You already have infrastructure running in AWS. It wasn't built with Terraform, or the state got lost, or someone clicked it together in the console. `infra-import` scans what's actually there and writes ready-to-use Terraform code plus the import script to adopt it into state — no more clicking through the console trying to reverse-engineer your own cloud.

```bash
infra-import --region us-east-1
```

That's it. Point it at a region, get back a full Terraform project mirroring your live infrastructure.

---

## Why

- **Adopt existing infra into Terraform** without rewriting it by hand
- **Document what's actually running** — the generated `.tf` files are a living inventory
- **Recover from lost state** — regenerate code + re-import when a state file goes missing
- **Audit your footprint** — see every VPC, bucket, role, and cluster in one organized tree
- **Lightweight** — a single ~5MB binary that shells out to the AWS CLI you already have. No 300-crate SDK, no heavy runtime.

---

## What you get

Run it:

```bash
infra-import --region us-east-1 --output ./imported
```

And it produces a full project:

```
imported/
├── networking/networking.tf      # VPCs, subnets, NATs, IGWs, TGWs, route tables, endpoints, EIPs
├── compute/compute.tf            # EC2 instances, ASGs, launch templates, key pairs
├── loadbalancing/loadbalancing.tf# ALBs, NLBs, target groups
├── security/security.tf          # Security groups, NACLs
├── iam/iam.tf                    # Roles, policies, users, groups, instance profiles
├── storage/storage.tf            # S3 buckets, EBS volumes, EFS
├── database/database.tf          # RDS, DynamoDB, ElastiCache
├── kubernetes/kubernetes.tf      # EKS clusters, node groups, addons
├── lambda/lambda.tf              # Lambda functions
├── containers/containers.tf      # ECS clusters, services
├── messaging/messaging.tf        # SQS, SNS, Kinesis
├── monitoring/monitoring.tf      # CloudWatch alarms, log groups
├── dns/dns.tf                    # Route53 zones, ACM certs, CloudFront
```

### Example generated code

`imported/networking/networking.tf`:

```hcl
resource "aws_vpc" "prod_vpc" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  enable_dns_support   = true
  tags = {
    "Name" = "prod-vpc"
  }
}

resource "aws_subnet" "prod_private_1a" {
  vpc_id                  = "vpc-0a1b2c3d4e5f"
  cidr_block              = "10.0.1.0/24"
  availability_zone       = "us-east-1a"
  map_public_ip_on_launch = false
}
```

`imported/import.sh`:

```bash
#!/bin/bash
# Generated by infra-import
set -e

# --- networking ---
terraform import aws_vpc.prod_vpc vpc-0a1b2c3d4e5f
terraform import aws_subnet.prod_private_1a subnet-0f1e2d3c4b5a
...
```

### Adopt it into state

```bash
cd imported
terraform init
bash import.sh        # imports every resource into Terraform state
terraform plan        # goal: "No changes. Your infrastructure matches the configuration."
```

Grab the right binary from [Releases](https://github.com/super-kawaii-projects/infra-import/releases/latest):

|----------|--------|

| Linux ARM64 | `infra-import-linux-arm64` |
| macOS Intel | `infra-import-darwin-amd64` |
| macOS Apple Silicon | `infra-import-darwin-arm64` |
| Windows | `infra-import-windows-amd64.exe` |

```bash
# example: Linux x86_64
curl -fsSL -o infra-import \
  https://github.com/super-kawaii-projects/infra-import/releases/latest/download/infra-import-linux-amd64
chmod +x infra-import
sudo mv infra-import /usr/local/bin/
```

Every release includes a `checksums.txt` — verify with `sha256sum -c`.

### Docker

```bash

```

## Prerequisites

- **AWS CLI** installed and configured (`aws configure`). infra-import calls the AWS CLI under the hood.
- **Terraform** (only needed when you run `import.sh` / `terraform plan`)
- AWS credentials with **read access** to the services you want to scan (see [IAM Permissions](#iam-permissions))

## Usage

```bash
# Scan everything in a region
infra-import --region us-east-1

# Use a named AWS profile
infra-import --region us-east-1 --profile production

# Scan a single category
infra-import --scope networking --region us-east-1

# Limit to one VPC (great for adopting a single environment)
infra-import --region us-east-1 --vpc-id vpc-0a1b2c3d4e5f

# Preview without writing anything
infra-import --dry-run

# Keep going past services you lack permissions for
infra-import --region us-east-1 --skip-errors

# Custom output directory
infra-import --region us-east-1 --output ./terraform/imported
```

### Flags

| Flag | Description | Default |
|------|-------------|---------|
| `-r, --region` | AWS region to scan | `us-east-1` |
| `-p, --profile` | AWS profile to use | (default profile) |
| `-s, --scope` | What to scan (see [Scopes](#scopes)) | `all` |
| `-o, --output` | Output directory | `./imported` |
| `--vpc-id` | Only resources in this VPC | (all) |
| `--dry-run` | Show what would be scanned, write nothing | off |
| `--skip-errors` | Don't abort when a service errors (e.g. permission denied) | off |

## How it works

1. Verifies your identity with `sts get-caller-identity`
2. Calls AWS CLI list/describe commands per service
3. Parses the JSON responses
4. Generates Terraform resource blocks with the relevant attributes
5. Writes organized `.tf` files grouped by service category
6. Emits an `import.sh` with a `terraform import` line for every discovered resource, using the correct import ID format per resource type

No AWS SDK is compiled in — it drives the AWS CLI you already trust and have configured. That keeps the binary tiny and the behavior transparent (every call is a plain `aws ...` command).

## FAQ / Troubleshooting

**"Auth failed: Is 'aws' installed and in PATH?"**
infra-import shells out to the AWS CLI. Install it and run `aws configure` first. Verify with `aws sts get-caller-identity`.

**A service errored and the whole run stopped.**
Add `--skip-errors` to continue past services you can't read (common with tightly scoped IAM). The skipped services are reported and just left out of the output.

**`terraform plan` shows changes after import.**
The generated code captures core attributes, not every last setting. Review the diff and add any missing attributes (tags, lifecycle rules, etc.) to the `.tf` files. The import itself is correct — the plan is just showing config that wasn't emitted.

**Does it modify my AWS account?**
No. Every call is read-only (list/describe). It only writes files to your output directory. The generated `import.sh` also only touches Terraform *state*, not AWS.

**Can I scan multiple regions?**
Run it once per region with different `--output` dirs, e.g. `--region us-east-1 --output ./imported/use1`.
